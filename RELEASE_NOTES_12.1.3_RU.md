# Tavrimo 12.1.3 — Static Schedule Provider

## Что изменено

- Добавлен реестр `data/schedules/manifest.json` для явного сопоставления номера группы с локальным ICS-файлом.
- При выборе группы Tavrimo сначала проверяет наличие статического снимка; если записи нет, продолжает использовать прежний Sync Gateway.
- Используется существующий `parseUniversityIcs()` и существующее `applyUniversitySchedule()` — второй календарь и отдельный механизм отображения не создаются.
- Добавлены проверки целостности VCALENDAR, количества VEVENT, повторений, отмен, DURATION и поддерживаемых часовых поясов. Если календарь прочитан частично, прежние данные не заменяются.
- Время создания снимка отделено от времени последней проверки файла; статический файл не показывается как live-синхронизация.
- Service Worker обновлён до 12.1.3 и кэширует реестр и загруженные календарные файлы для offline-поведения.

## Демонстрационный календарь включён

- Добавлен календарный снимок Vuzio: `data/schedules/rea-15-14d-gg04-266.ics`.
- В файле 46 занятий за период **9–23 ноября 2026 года**. Это не семестровый календарь и не live-подписка.
- Реестр `data/schedules/manifest.json` связывает файл с группой `15.14Д-ГГ04/266`. В заголовке исходного календаря Vuzio группа отображается как `15.14Д-ГГ04/26б`; идентификатор группы в Tavrimo взят из выбранной группы пользователя и скриншота.
- Источник в самом календаре обозначен `PRODID:-//Vuzio//RANEPA schedule//RU`. Это календарная лента Vuzio, а не прямой экспорт из официального портала РЭУ.
- Все 46 событий разобраны текущим `parseUniversityIcs()`. Времена `Z` преобразуются в `Europe/Moscow` (UTC+3); преподаватели и аудитории сохранены. Две одновременные записи физкультуры 16 ноября оставлены как разные потоки.
- При загрузке Tavrimo показывает, что это демонстрационный снимок, его источник и диапазон дат. После первой успешной загрузки события остаются в локальном хранилище; Service Worker кэширует ICS для offline.

Полноценная автоматическая синхронизация с `rasp.rea.ru` не восстановлена: проблема HTTP 403 остаётся отдельной задачей после демонстрации.
