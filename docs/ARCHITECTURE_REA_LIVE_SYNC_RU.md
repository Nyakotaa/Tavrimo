# Архитектура Tavrimo REA Live Sync

```text
┌──────────────────────┐
│      iPhone PWA      │
│  Tavrimo / Safari    │
└──────────┬───────────┘
           │ GET /api/rea/schedule?group=...
           │ If-None-Match
           ▼
┌──────────────────────┐
│   Tavrimo Sync       │
│       Gateway        │
│ Node + Express +     │
│ Playwright/Chromium  │
└──────────┬───────────┘
           │ официальный пользовательский поток
           ▼
┌──────────────────────┐
│      rasp.rea.ru     │
│ группа → расписание  │
│ → официальный .ics   │
└──────────────────────┘
```

## Почему не прямой fetch из PWA

В официальных материалах, которые удалось проверить, портал предоставляет поиск расписания и экспорт календаря, но документированного публичного API для браузерного использования найдено не было. Поэтому для автоматической загрузки без ручного `.ics` нужен серверный слой.

## Жизненный цикл

1. Пользователь один раз указывает группу.
2. Gateway запрашивает актуальный экспорт у официального портала.
3. PWA разбирает iCalendar и сопоставляет события со старой версией.
4. Если время пары изменилось и ручная задача пересекается с новым занятием, задача снимается со слота.
5. Новое расписание сохраняется локально и доступно без сети.
6. Следующая проверка использует ETag; при отсутствии изменений сервер возвращает `304 Not Modified`.

## Ограничение

iOS не гарантирует выполнение JavaScript в полностью закрытом PWA. Поэтому нельзя обещать мгновенное обновление во время закрытого приложения. Проверка происходит на старте/возврате и периодически, когда приложение открыто.
