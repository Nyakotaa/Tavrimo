# Деплой Tavrimo + автоматической синхронизации РЭУ

Tavrimo может быть опубликован одним Docker-контейнером: веб-интерфейс и `/api/rea/*` работают на одном HTTPS-адресе. Это самый простой вариант, если нужна автоматическая загрузка расписания по номеру группы.

## Вариант A — один Docker-сервис

1. Скопируйте весь репозиторий на сервер или подключите его к Render/другому Docker-хостингу.
2. Используйте корневой `Dockerfile`.
3. Откройте выданный HTTPS-адрес.
4. Проверьте `https://YOUR-HOST/api/rea/health` — должен вернуться JSON с `ok: true`.
5. Откройте Tavrimo в Safari и добавьте его на экран «Домой».
6. Введите номер группы. Расписание должно загрузиться без ручного `.ics`.

## Вариант B — GitHub Pages + отдельный Sync Gateway

GitHub Pages может отдавать статический PWA, но не исполняет Node/Playwright. Поэтому Gateway должен быть отдельным HTTPS-сервисом.

В `config.js` укажите:

```js
window.TAVRIMO_CONFIG = {
  syncEndpoint: 'https://YOUR-SYNC-HOST.example/api/rea/schedule',
  syncIntervalMinutes: 15,
  requestTimeoutMs: 25000
};
```

Gateway должен разрешать CORS для origin GitHub Pages.

## Запуск без Docker

Требуется Node.js 20+ и Chromium для Playwright:

```bash
npm install --prefix sync-service
npx playwright install chromium
node sync-service/server.mjs
```

## Поведение обновлений

Tavrimo проверяет расписание:

- сразу после сохранения группы;
- при запуске;
- при возвращении из фона;
- каждые 15 минут, пока приложение открыто и есть интернет.

При изменении официального календаря приложение сравнивает события и применяет новый вариант. Если изменение пары приводит к конфликту с ручной задачей, задача снимается со времени и попадает во входящие.

### Важное ограничение

iOS не гарантирует выполнение JavaScript в полностью закрытом PWA, поэтому невозможно гарантировать мгновенную проверку в момент изменения на сайте РЭУ, когда приложение полностью выгружено из памяти. Следующий запуск/возврат выполняет актуализацию.
