# Tavrimo 12.0.0 — QA: REA Live Sync

## Покрытие

Проверены статически:
- JavaScript и Service Worker syntax;
- ручное планирование и конфликты с парами;
- parser iCalendar и стабильность ID занятий;
- миграция локальных данных;
- onboarding;
- live-sync hooks, ETag/304, CORS и Express 5 SPA fallback;
- локальные ресурсы и manifest;
- размеры и целостность иконок.

## Автосинхронизация

Runtime:
- после сохранения группы запускается принудительная синхронизация;
- на старте выполняется проверка при наличии группы и сети;
- при `visibilitychange` / `pageshow` выполняется проверка;
- пока PWA открыто и онлайн, проверка повторяется раз в 15 минут;
- `If-None-Match`/`ETag` позволяет получить `304` без повторного импорта;
- API-ответы не должны попадать в Service Worker cache;
- empty remote result не затирает последнее известное расписание, если локально уже есть события.

## Gateway

- upstream: `https://rasp.rea.ru/`;
- Playwright/Chromium получает официальный экспорт календаря;
- добавлены CORS headers для отдельного origin;
- добавлен rate limit;
- одинаковая группа дедуплицируется по in-flight запросу;
- Express 5-compatible SPA fallback;
- `/api/rea/health` доступен для smoke test.

## Ограничения тестовой среды

Физического iPhone в тестовой среде нет, а бинарник Chromium для Playwright в runtime-окружении не установлен. Поэтому реальный iPhone smoke test и живой запрос к rasp.rea.ru через Playwright следует провести после деплоя.
