# Автоматическая синхронизация расписания РЭУ

## Зачем нужен Sync Gateway

Официальный портал РЭУ (`https://rasp.rea.ru/`) позволяет найти расписание по группе и экспортировать его в iCalendar (`.ics`). На публичной странице расписания нет документированного публичного API, который можно было бы безопасно вызвать из GitHub Pages непосредственно из браузера. Поэтому Tavrimo 12 использует отдельный Sync Gateway.

Gateway открывает официальный портал РЭУ в автоматизированном браузере, вводит номер группы, получает официальный экспорт календаря и отдаёт его приложению. Само приложение хранит расписание локально и сравнивает новые версии по ETag/хэшу.

## Важно

Gateway не является источником расписания. Источник — официальный портал РЭУ. При расхождении ориентируйтесь на `rasp.rea.ru`.

## Самый простой запуск

### Вариант 1 — один адрес (рекомендуется для релиза)

Разверните корень репозитория в Docker. В комплекте уже есть корневой `Dockerfile`, который использует образ Playwright с Chromium. После запуска один адрес обслуживает и PWA, и API. В этом режиме `config.js` оставьте без изменений: используется `/api/rea/schedule`.

### Вариант 2 — GitHub Pages + отдельный Gateway

GitHub Pages остаётся хостингом интерфейса, а Gateway запускается отдельно. После публикации Gateway укажите в `config.js` его публичный HTTPS-адрес.

Для запуска без Docker на сервере с Node.js 20+:

```bash
npm install --prefix sync-service
npx playwright install chromium
node sync-service/server.mjs
```

Проверка здоровья: `GET /api/rea/health`.

В `config.js` при размещении PWA отдельно от сервера укажите:

```js
window.TAVRIMO_CONFIG = {
  syncEndpoint: 'https://example.example/api/rea/schedule',
  syncIntervalMinutes: 15,
  requestTimeoutMs: 25000
};
```

Если PWA и Gateway работают на одном origin, ничего менять не нужно: по умолчанию приложение использует `/api/rea/schedule`.

## Render / Railway / VPS

Для деплоя используйте корень репозитория как build context. Стартовая команда:

```bash
npm install --prefix sync-service
node sync-service/server.mjs
```

Для Docker используйте корневой `Dockerfile`.

## Как работает обновление

- при первом запуске после сохранения группы приложение делает запрос;
- при возвращении из фона, если есть интернет, делает проверку;
- пока приложение открыто, проверка повторяется раз в 30 минут;
- если ETag не изменился, расписание не трогается;
- если изменился, приложение импортирует новую версию, сопоставляет пары со старыми ID и повторно проверяет конфликты ручных задач;
- старое расписание остаётся доступным офлайн, если сервер или портал временно недоступны.

### Что считается изменением

Изменением считается изменение даты, времени, предмета, типа, преподавателя или аудитории. Если у события есть стабильный `UID`, Tavrimo сохраняет внутренний ID события, поэтому связанные задачи не теряют ссылку при переносе пары.

## Ограничение iOS

iOS не гарантирует постоянное выполнение JavaScript в фоне для PWA. Поэтому автоматическая проверка выполняется при запуске приложения, возвращении в него и периодически, пока оно открыто. Пока приложение полностью закрыто, момент фонового обновления контролируется iOS.

## CORS и отдельный GitHub Pages

Gateway уже отдаёт CORS-заголовки для GET/OPTIONS и разрешает заголовок `If-None-Match`. Это необходимо, когда PWA и Gateway находятся на разных доменах. Для продакшена рекомендуется HTTPS.

## ETag

Gateway формирует ETag на основе полного `.ics`. Tavrimo сохраняет ETag и отправляет `If-None-Match`; ответ `304` считается успешной проверкой без изменений.
