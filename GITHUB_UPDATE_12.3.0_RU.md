# Обновление Tavrimo до 12.3.0 через GitHub Web

## Важно перед публикацией

1. Сделай экспорт JSON из текущего Tavrimo и сохрани файл в безопасное место.
2. Убедись, что `main` содержит Tavrimo 12.2.0.
3. Создай резервную ветку `backup-before-12.3.0` от `main`.
4. Создай рабочую ветку `update-12.3.0` от `main`.

## Загрузка файлов

Проще всего загрузить содержимое `Tavrimo_12.3.0_GitHub_Patch.zip` в корень репозитория. В патче сохранены относительные пути. Распакуй ZIP на компьютере, затем на странице ветки `update-12.3.0` выбери **Add file → Upload files** и перетащи все папки/файлы из распакованного патча.

Если GitHub Web не принимает перетаскивание всех путей за раз, дели по папкам, но не перемещай файлы из исходной структуры:

- корневые файлы;
- `docs/`;
- `sync-service/`;
- `tools/`.

Commit message: `Release Tavrimo 12.3.0 - external calendars and greeting`.

## Проверка перед PR

- `VERSION` должен содержать `12.3.0`.
- В корне должны появиться `calendar-update.css`, `CALENDAR_IMPORT_GUIDE_RU.md`, `QA_12.3.0_RU.md`.
- В `sync-service/` должны присутствовать `calendar-feed.mjs`, обновлённый `server.mjs`, `package.json` и `test-calendar-feed.mjs`.
- В `tools/` должны присутствовать новые тесты календарей и релиза.
- `index.html` должен подключать `calendar-update.css?v=12.3.0` и `app.js?v=12.3.0`.

Создай Pull Request: base `main`, compare `update-12.3.0`. Проверь список файлов и отсутствие неожиданных удалений. Затем можно объединить PR.

## После merge: два независимых деплоя

### 1. GitHub Pages (frontend)

Дождись workflow Pages. Открой сайт и сделай жёсткое обновление: `Ctrl + F5`. При установленном PWA закрой и открой его заново; Service Worker использует cache key 12.3.0.

После публикации фронтенда будут доступны:
- приветствие по локальному времени и поле имени в настройках;
- импорт `.ics`-файлов;
- менеджер внешних календарей.

### 2. Render Sync Gateway (backend)

URL-подписки Google/Outlook/iCloud не заработают, пока Render не развернёт новый `sync-service` с endpoint `POST /api/calendar/feed`.

Открой Render Dashboard → существующий сервис `tavrimo-rea-sync` → Events/Deploys. Убедись, что он отслеживает репозиторий `Nyakotaa/Tavrimo` и ветку `main`, затем дождись успешного deploy нового commit. Не создавай новый Render-сервис и не меняй переменные окружения без необходимости.

После deploy проверь в Tavrimo добавление внешнего календаря по read-only HTTPS iCalendar URL. Если endpoint ещё не обновился, импорт `.ics`-файлов продолжит работать, а ссылка покажет понятную ошибку.

## Безопасность

Секретные Google/Outlook/iCloud ICS URL дают право читать календарь. Они хранятся в локальных данных Tavrimo и попадают в JSON backup. Не публикуй такие ссылки и резервные копии. При утечке сбрось/отзови ссылку у провайдера и подключи новую.
